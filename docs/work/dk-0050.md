## Scope

Under `verbatimModuleSyntax`, `import { type A } from "./x.ts"` still loads the
module at runtime, while `import-x/no-cycle` treats it as type-only, so a runtime
cycle closed by one passes lint. Enable
`@typescript-eslint/no-import-type-side-effects` for every linted TypeScript
file and autofix existing imports to `import type`.

## Criteria

- ESLint rejects an import whose specifiers are all inline `type`.
- No such import remains, and the containerized gate passes with the contract
  cases unchanged.

## Decisions

- D1 (user, 2026-11-26; answers q-delivery-kit-type-side-effects): Approve: enable @typescript-eslint/no-import-type-side-effects and autofix inline-only type imports to import type; ships in the next functional release.

## Outcome

`@typescript-eslint/no-import-type-side-effects` is an error for every `.ts` and
`.mts` file ESLint lints, configured beside `ts.configs.recommended` in
`eslint.config.mjs`. The eight inline-only type imports in `src/` and
`tests/contract/cases/` now use `import type`; mixed imports are unchanged. A
temporary inline-only type import failed lint. The contract cases are unchanged
apart from one import form.
