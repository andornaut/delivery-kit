## Scope

Extend cycle detection to every TypeScript and JavaScript module in `src/`,
`scripts/` and `tests/`, with type-only imports counted as edges. Extend the
ESLint `import-x/no-cycle` rule from `src/` to `scripts/` and `tests/`.

## Criteria

- `scripts/imports.test.ts` rejects any cycle in `src/`, `scripts/` or
  `tests/`, type-only edges included, and a synthetic type-only cycle fails it.
- ESLint reports a cycle in any of the three trees.
- The containerized gate passes with the contract cases unchanged.

## Decisions

- D1 (user, 2026-11-25; answers q-delivery-kit-dk0046-release): Carry dk-0044, dk-0045 and dk-0046 in the next functional Delivery Kit release; no 8.3.1 now.

## Outcome

`scripts/imports.test.ts` parses every `.ts`, `.mts` and `.mjs` module in
`src/`, `scripts/` and `tests/` with `ts.preProcessFile`. It counts type-only
imports, re-exports, side-effect imports and literal dynamic imports as edges,
and synthetic cases prove that type-only and mixed cycles fail. ESLint
`import-x/no-cycle` covers the same trees. Widening the scope found the
type-only cycle `tests/contract/lib/adapter.ts` with `node-adapter.ts`, so the
shared interfaces moved to `implementation.ts`. The contract cases are
unchanged.
