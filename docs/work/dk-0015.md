## Scope

Short design summaries in `docs/design/<area>.md`, one work file per approved task in
`docs/work/<id>.md`, and the convention in the [work-file README](README.md). Work files are
written for the 4.6.1 and 4.6.2 contents and the approved roadmap items.

## Criteria

- Each design area has a summary that links its topic docs and an index table of ID, title and
  link, with no status column.
- Each work file has the convention's front matter and the Scope, Criteria, Decisions and
  Outcome sections.
- The README Documentation table lists the design and work indexes.
- The npm package ships the design summaries and excludes `docs/work/`.

## Decisions

- The topic docs stay where they are and remain the detailed reference.
- Live progress stays in the protocol state root; a work file records only milestones.
- Design summaries are packaged with the topic docs; work files are repository records and are
  not packaged.
- Protocol work reference `dk-work-files`.

## Outcome

Delivered with the change that adds `docs/design/` and `docs/work/`.
