## Scope

Phase 2 of the coordination simplification plan: the runner appends typed events to
`var/games/<g>/bus/events.jsonl` and coordination-kit ingests them.

## Criteria

- Typed appends (`attempt`, `gate`, `push`, `ci`, `deploy`, `runner.started`) by the runner as the
  only writer, as atomic lines; a failed append never stops a departure.
- `complete` becomes a projection with a unique `(game, complete, sha)` key and is still delivered
  as a message to `reports.recipient`.
- An ingest cursor file in `bus/` lets `status` report drained without reading the store; a torn
  last line is quarantined; the log rotates after ingest.
- Rolling back to 6.0 converts uningested lines into outbox files.

## Decisions

- Protocol work reference `dk-6-1`; built against the coordination-kit 2.0 contract:
  `id = sha256(game, type, key)`, `kind` one of six families, `type` the exact event kind,
  coordinator CLI range `>=2.0.0 <3.0.0`.
- Rollback drains `events.jsonl` with one 2.0 `events ingest` before a 6.0 runner starts, instead
  of converting lines back into outbox files; the 2.0 CLI keeps `events flush` for the 6.0 outbox.
- A torn last line is terminated with a newline at startup: a complete JSON fragment becomes its
  event, any other fragment a malformed line for ingest to quarantine, so the next append never
  merges into it.
- `detail` keeps the `<project> bus:` prefix the 6.0 outbox delivered, so imported and new lines
  read alike.
- A push under `deploy.mode` `none` appends `deploy_disabled` (deploy, skipped), so COMPLETE and
  the `work` range need no game configuration.
- The `work` range starts at `bus/last-complete.sha`, the last commit whose push, CI and deploy
  events the runner saw succeed.
