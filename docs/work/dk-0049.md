## Scope

After an install step exits 0 in a checkout with `package-lock.json`, verify
that every optional package the lock lists for the container's platform (its
`os`, `cpu` and `libc` match) is present in the installed tree. A missing one
blocks the gate as an infrastructure failure naming the package, like an
install that could not reach the registry, rather than letting the gate steps
fail. Checkouts without `package-lock.json` and an empty install are unchanged.

## Criteria

- The selection of expected optional packages is a pure function of the lock
  and the platform, with direct tests for os, cpu and libc matching.
- A gate whose install skipped a matching optional package reports a blocked
  outcome naming it, and a non-matching optional package is never required.
- The containerized gate passes with the contract cases unchanged.

## Decisions

- D1 (user, 2026-11-25; answers q-delivery-kit-optional-natives): Approve: after a passing install with package-lock.json, verify every platform-matching optional package is installed and block the gate as infrastructure when one is missing. Ships in the next functional release.
- D2 (user, 2026-11-25; answers q-delivery-kit-dk0049-omit): Honour npm's effective omit: read npm's omit configuration inside the gate container and skip omitted kinds, so the check never requires a package npm was told to skip.

## Outcome

After a passing install of a commit whose `package-lock.json` (lockfileVersion 2
or 3) lists optional packages, the gate reads the container's platform with
`node`, derives the optional entries npm installs there (os, cpu, libc and
engines matching, negation, reachability from the root and workspace folders)
and lists which are present. A missing one blocks the gate as infrastructure
with a reason naming the package, the platform and the install log. A skipped
optional entry's own dependencies are not required, so the three games' current
locks raise no false block. `devOptional` and bundled entries are not checked.
Per D2 the selection follows npm's effective omit: `npm config get omit` read in
the container, joined with the omit flags of the install command and less its
`--include` kinds. An omitted entry and what only it reaches are not expected,
and the block reason names any omitted kinds.
Unit tests cover the selection, the reason, the container scripts and the gate
flow; the contract cases are unchanged.
