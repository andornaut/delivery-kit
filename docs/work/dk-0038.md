## Scope

Preserve the approved SHA of a one-off request, serialize deployments, retain pending
builds on transient remote lookup errors, and make detached first start work on a fresh
layout. Build once during the combined local verification targets.

## Criteria

- One-off approval governs the exact SHA gated and pushed. A failed lookup remains distinct
  from a changed ref.
- CI completion and scheduled retries cannot deploy the same pending build concurrently.
- Transient retry lookup errors retain pending evidence and leave the resident runner active.
- Detached first start creates its output directory. Combined checks keep both suites and
  build only once.

## Decisions

## Outcome

Requests carry one selected SHA through gate and push. Pending deployment operations
serialize separately from the departure lock. Transient Git lookup errors retain the
pending build. Detached start creates its log directory, and combined checks reuse the
contract build for the unit suite.
