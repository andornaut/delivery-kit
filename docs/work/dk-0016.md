## Scope

`runner unit --game ID` prints an explicit systemd user unit for one game's resident runner,
derived from the game layout.

## Criteria

- The unit names the working directory, the resolved `node` binary, the game's `dist/cli.js`,
  `PATH`, `DELIVERY_KIT_ROOT`, `Restart=on-failure` with a start limit,
  `SuccessExitStatus=143` and `RestartPreventExitStatus` for the duplicate-runner exit.
- The command only prints the unit. It is re-run after a Node upgrade.
- [runner](../reference/runner.md) gains a Supervision section and the upgrade procedure, replacing the
  statement that no systemd unit is involved.

## Decisions

- Protocol work reference `dk-runner-supervision`.
- Per-game rollout (stop the hand-started runner, install the unit, verify the lock holders,
  re-adopt) is each game Tech's work, coordinated by game-coordinator.
- Start at boot requires the operator to enable lingering for the user (`loginctl enable-linger`).

## Outcome

Shipped in 4.7.0. `delivery-kit runner unit --game ID` prints the unit and changes nothing. A runner refused by a live lock holder exits 3, which the unit excludes from restarts.
