## Scope

Extract the registry, messages, transports, harness adapters, request ledger, work protocol and
enrollment into a new coordination kit 1.0, which also gets the work-file check and report
commands. delivery-kit 5.0 depends on it.

## Criteria

- delivery-kit declares the coordination-kit version range it supports, and its pin guard checks
  that range at runner start.
- Work plan artifacts keep their hash and gain optional `path` and `commit` fields that point at
  the repository work file, with no schema generation change.
- The work-file report joins work-file milestones with live protocol state.

## Decisions

- Protocol work reference `dk-coordination-split`.
- Related [ck-0001](https://github.com/andornaut/coordination-kit/blob/main/docs/work/ck-0001.md)
  is the extraction itself, into coordination-kit 1.0.0.
- The coordination kit's role, session, worktree and repository are created first, by
  game-coordinator.
- The coordination-kit backlog moves to the new kit's repository with the split.
- The CLI drops the `inbox`, `message`, `ledger`, `protocol`, `harness`, `claude` and `codex`
  groups; each exits 2 with a one-line hint naming the `coordination-kit` command, with no alias.
- The moved library subpaths are not re-exported; the package exports only `build/source-identity`
  and its alias.
- coordination-kit is a devDependency on its release asset, inlined into the bundles, so
  `dist/cli.js` still imports only `node:` builtins.
- The supported range `>=1.0.0 <2.0.0` is declared once in `src/bus/pin.ts`; `run` refuses to
  start and `status` reports unsupported outside it.
- The runner keeps cadence and calls `deliverScheduledReview`; `emitEvent` keeps per-commit
  tracking and the `complete` event in `recordEvent`'s `underLock` step.
- The contract suite keeps the runner-level cases, including the event delivery cases until
  coordination-kit carries them.

## Outcome

Shipped in 5.0.0.
