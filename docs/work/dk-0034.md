## Scope

The runner appends `gate_passed` (kind `gate`, status `ok`) when a departure's gate passes,
before its push. coordination-kit derives COMPLETE from a gate outcome of ok or skipped, push
ok, CI ok and deploy ok or skipped; without `gate_passed` only docs-only pushes, which log
`gate_skipped`, complete. Ships in 6.1.2 from a `release-6.1` branch and in 7.0.

## Criteria

- Every departure whose gate passes appends exactly one `gate_passed` line for its commit,
  deduplicated by type and key like the other events.
- A departure that skips its gate still appends only `gate_skipped`.
- A contract case with the real coordination-kit CLI shows COMPLETE for a full departure.
- CI runs on `release-*` branches, so the 6.1.2 tag waits for green CI on its commit.
