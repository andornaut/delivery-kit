## Scope

Phase 4 of the coordination simplification plan: remove the work protocol import from runner
adoption.

## Criteria

- Identity comes only from the `runner.started` record; owner attestation is optional and
  admission depends on neither.
- The `status` field `observer_adoption` is redefined from `runner.started` and the optional
  attestation.

## Decisions

- D1 (user, 2026-11-19): identity comes only from `runner.started`; owner attestation and the
  registry `operations.<game>.lastAdoption` audit lookup are dropped. `observer_adoption` is
  `current` when the latest `runner.started` (in `events.jsonl`, else the newest rotated log)
  carries the running token, the cursor shows that line ingested in the same file and the last
  seen coordinator CLI is in range; `stale` when its token differs; otherwise `unknown`. The reason
  is null only for `current`.
- D2 (user, 2026-11-19): the runner stops emitting `resident-identity-changed`; `runner.started`
  replaces it. The type stays in the legacy mapping so a 6.0 outbox still imports it.
- D3 (user, 2026-11-19): `COORDINATOR_CLI_RANGE` is `>=3.0.0 <4.0.0` with the same defer-only
  rules. `COORDINATION_KIT_RANGE`, the build-time range of the bundled copy, is `>=2.0.1 <4.0.0`:
  the bundle uses only `build/registry`, `build/review` and `build/shared`, which 3.0 keeps
  unchanged, so both the current 2.0.1 bundle and a later 3.x bundle pass the package check and
  the move to 3.x is a pin change only. The lower bound is the current 2.0.1 pin. ESLint refuses any `build/protocol` import in source, tests and tooling.

## Outcome

Shipped in 7.0.0.
