## Scope

Remove redundant executable cases while preserving distinct behaviours and critical
edges. Compare isolated baseline and after runs at the same worker and container
limits.

## Criteria

- Record executed case counts and elapsed suite time separately for comparable runs.
- Name the retained coverage for each removal and document any accepted gap.
- Preserve required checks and test timeouts.

## Decisions

- D1 (user, 2026-11-22; answers q-delivery-kit-0030-target): Use measured test pruning without a fixed case-count quota. Record comparable runtime, executed counts and preserved coverage.

## Outcome

The same focused suites went from 76 to 73 executed cases. Unit suite time was
2.68 s before and 2.46 s after. Contract suite time was 39.34 s before and 40.10 s
after. This sample showed a case reduction and no overall wall-clock speedup.

- The dirty-source and mismatched-HEAD rejection checks live in the gate tests.
  They check the precise reason, no container work, no output and preserved source.
- One gate run checks the verified source mount and pre-copy tree verification.
- The packaged API check reuses saved pack bytes for the wrong-inventory probe.
  All of its rejection probes remain.

The duplicate dirty and wrong-HEAD fixtures were retired. The independent real-shell
success and source isolation cases remain.
